# Учёт выполненных работ

Небольшой сайт для учёта работы сотрудников и расчёта выплат инвесторам по
морским прогулкам на катерах. Два связанных раздела:

- **Зарплаты** — форма (сотрудник, вид работы, часы/кол-во, ставка, дата
  работы), фильтр по неделям и по сотруднику.
- **Рейсы и инвесторы** — учёт рейсов по катерам: доход, канал продажи
  (напрямую / через агрегатора), комиссия управляющего, прямые расходы
  (оплата капитана/гида, топливо, стоянка, разовые расходы) и автоматический
  расчёт выплаты инвестору. При добавлении рейса запись об оплате
  капитана/гида **автоматически** появляется и в разделе «Зарплаты» — вносить
  её дважды не нужно.

Данные хранятся в SQLite (файл `workhours.db`, создаётся автоматически при
первом запуске).

## Как считается выплата инвестору

```
Комиссия = Доход рейса × Комиссия (%)
Прямые расходы = оплата капитана/гида + топливо + стоянка + доп. расходы
Остаток = Доход − Комиссия − Прямые расходы
Инвестору = Остаток / 2
Мне = Комиссия + Остаток / 2
```

## Как отредактировать список катеров, сотрудников и видов работ

Откройте `app.py` и найдите в начале файла:

```python
EMPLOYEES = [...]      # список сотрудников (капитаны, гиды и т.д.)
WORK_TYPES = [...]     # виды работ/рейсов со стандартной ставкой и часами
BOATS = [...]          # катера: инвестор, комиссия (%), топливо/стоянка по умолчанию
```

Для `BOATS` у каждого катера можно задать:
- `commission_direct` — комиссия (%) при прямой продаже
- `commission_aggregator` — комиссия (%) при продаже через агрегатора/агента
  (если комиссия всегда одна и та же — укажите одинаковое число в обоих полях)
- `fuel`, `mooring` — стандартные суммы топлива и стоянки за рейс (подставляются
  в форму автоматически, но перед сохранением их можно поправить вручную —
  например, если рейс был дальний или стоянка в этот раз дороже обычной)

При выборе канала продажи **«Смешанно / другое»** комиссия не подставляется
автоматически — её нужно ввести вручную (для случаев, когда часть билетов на
рейс продана напрямую, а часть — через агрегатора, и итоговая комиссия
получается смешанной).

Рейсы можно редактировать и удалять в любой момент (кнопки ✎ и ✕ в таблице
рейсов) — при удалении рейса связанная запись в «Зарплатах» удаляется вместе
с ним, при редактировании — обновляется, а не дублируется.

## Недельный и месячный фильтры

- В разделе «Зарплаты» — фильтр по неделям (платежи еженедельные), с
  понедельника по воскресенье.
- В разделе «Рейсы и инвесторы» — фильтр по месяцам (выплаты инвесторам
  считаются помесячно), плюс фильтр по конкретному катеру.

## Запуск локально

Понадобится Python 3.9+.

```bash
cd workhours-app
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
python app.py
```

Откройте в браузере: **http://127.0.0.1:5000**

## Как выложить в интернет (бесплатные варианты)

Проще всего — **Render.com** (есть бесплатный тариф) или **PythonAnywhere**
(бесплатный тариф с постоянной файловой системой — данные не будут
очищаться, в отличие от Render Free).

### Render.com
1. Зарегистрируйтесь на [render.com](https://render.com) и подключите свой
   GitHub-аккаунт.
2. Загрузите эту папку в новый репозиторий на GitHub (можно прямо через
   веб-интерфейс GitHub — "Add file → Upload files").
3. В Render: **New → Web Service**, выберите этот репозиторий.
4. Настройки сборки:
   - **Build Command:** `pip install -r requirements.txt`
   - **Start Command:** `gunicorn app:app`
5. Нажмите **Create Web Service** — через пару минут сайт будет доступен по
   ссылке вида `https://ваше-приложение.onrender.com`.

⚠️ На бесплатном тарифе Render файловая система не постоянная — база может
очищаться при перезапуске сервиса.

### PythonAnywhere (рекомендуется — данные не теряются)
1. Регистрация на [pythonanywhere.com](https://pythonanywhere.com), тариф
   **Beginner** (бесплатный).
2. Вкладка **Files** → загрузите архив, распакуйте через консоль (`unzip`).
3. Вкладка **Web** → **Add a new web app** → **Flask** → укажите путь к
   `app.py`.
4. Проверьте в открывшемся WSGI-файле, что путь `project_home` указывает
   именно на папку с вашим `app.py` (а не на шаблонную папку `mysite`,
   которую PythonAnywhere создаёт по умолчанию).
5. Нажмите **Reload**.

## Важно про данные

- База данных — это один файл `workhours.db` рядом с `app.py`.
- Резервная копия: можно в любой момент скачать файл `workhours.db` с
  сервера и открыть его любым SQLite-браузером (например, DB Browser for
  SQLite) — там видны все записи в исходном виде.
- Если сайт уже работал раньше (старая версия без раздела «Рейсы») — при
  следующем запуске база автоматически обновится: нужные таблицы будут
  добавлены сами, старые записи не потеряются.
