# Учёт выполненных работ

Небольшой сайт для учёта работы сотрудников: форма (сотрудник, вид работы,
часы/кол-во, ставка, дата работы), фильтр по неделям и по сотруднику,
таблица записей за период, сумма по каждому сотруднику и общая сумма за
выбранный период. Данные хранятся в SQLite (файл `workhours.db`, создаётся
автоматически при первом запуске).

## Как отредактировать список сотрудников и видов работ

Откройте `app.py` и найдите в начале файла два списка:

```python
EMPLOYEES = [
    "Иван Петров",
    "Мария Сидорова",
]

WORK_TYPES = [
    {"name": "Сварка каркаса", "rate": 1500, "hours": 5},
    {"name": "Покраска корпуса", "rate": 1200, "hours": 3},
    {"name": "Электромонтаж", "rate": 1800, "hours": 4},
]
```

Замените их на свои — просто отредактируйте текст и сохраните файл (для
`WORK_TYPES` `rate` — обычная ставка за этот вид работы, `hours` — обычная
длительность в часах; оба значения подставятся в форму автоматически при
выборе вида работы, но их можно поправить перед сохранением).

Если в форме выбрать «+ Другой / Другое (ввести вручную)» — можно добавить
сотрудника или вид работы, которых нет в списке; они не потеряются и сразу
появятся в фильтре по сотрудникам.

## Недельный фильтр

Платежи еженедельные, поэтому на странице есть выбор недели (с понедельника
по воскресенье) — по умолчанию показывается текущая неделя. Есть также
вариант «Все периоды» для просмотра всей истории. Дата, по которой
считается неделя — это «Дата работы», указанная в форме при добавлении
записи (по умолчанию подставляется сегодняшняя, но её можно изменить,
например, если вносите запись задним числом).

## Запуск локально

Понадобится Python 3.9+.

```bash
cd workhours-app
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
python app.py
```

Откройте в браузере: **http://127.0.0.1:5000**

## Как выложить в интернет (бесплатные варианты)

Проще всего — **Render.com** (есть бесплатный тариф):

1. Зарегистрируйтесь на [render.com](https://render.com) и подключите свой
   GitHub-аккаунт.
2. Загрузите эту папку в новый репозиторий на GitHub (можно прямо через
   веб-интерфейс GitHub — "Add file → Upload files").
3. В Render: **New → Web Service**, выберите этот репозиторий.
4. Настройки сборки:
   - **Build Command:** `pip install -r requirements.txt`
   - **Start Command:** `gunicorn app:app`
5. Нажмите **Create Web Service** — через пару минут сайт будет доступен по
   ссылке вида `https://ваше-приложение.onrender.com`.

Аналогично работает на **Railway.app** и **PythonAnywhere** — общий принцип
тот же: загрузить код, указать команду запуска `gunicorn app:app`.

Если сайт уже развёрнут и вы просто обновляете список сотрудников/видов
работ в `app.py` — на Render достаточно загрузить обновлённый файл в тот же
GitHub-репозиторий (Add file → Upload files → заменить `app.py`), и Render
сам пересоберёт и перезапустит сайт.

## Важно про данные

- База данных — это один файл `workhours.db` рядом с `app.py`. На
  бесплатных тарифах некоторых хостингов (например, Render Free) файловая
  система не постоянная и **может очищаться при перезапуске сервиса**. Для
  учебного/личного использования это обычно не критично, но если данные
  должны сохраняться надёжно и долго — на Render стоит подключить платный
  "Persistent Disk", либо перейти на внешнюю БД (например, бесплатный
  PostgreSQL на Render/Railway).
- Резервная копия: можно в любой момент скачать файл `workhours.db` с
  сервера и открыть его любым SQLite-браузером (например, DB Browser for
  SQLite) — там видны все записи в исходном виде.
- Если сайт уже работал раньше (старая версия без даты работы) — при
  следующем запуске база автоматически обновится: для старых записей дата
  работы будет взята из даты их добавления.
